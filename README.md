# hxyfront-62006 珠宝镶嵌 · 裸石镶位租约对账台

把白板分拣升级为**可续作的对账台**：裸石凭 TTL 租约占住镶位，两位师傅同交一位只放行先到者，
晚到者进候补并留冲突现场；订单号/石重一变，占用与租约立即失效重算；工位容量满则 FIFO 排队；
分拣结果走保险台账 outbox，本地再改先冲正再重报，回执对不上两版都留；写入失败只重投未入账报文。

## 机制对照

| 业务诉求 | 实现 |
| --- | --- |
| 裸石占住镶位并带租约 | 每镶位一份租约：TTL 45s + 单调递增 fencing token + 立约指纹 |
| 两师傅同交一位，先到先得 | 命令单队列串行处理，后到者进 waitlist，记录冲突租约/持位方/迟到毫秒数 |
| 订单号或石重一变立即失效 | `订单号|石重` 指纹比对：改单 v+1、租约即刻 revoke、结果作废、队列候补摘出重算 |
| 工位容量满排队 | 容量 3 的信号量 + FIFO 队列；完工/到期自动 pump 补位（位仍被占则转候补） |
| 分拣结果报保险台账 | outbox：`RPT:<石>:<指纹>` 幂等键，pending / confirmed / mismatch 三态 |
| 本地再改要冲正重报 | 改单对已入账报文挂 `REV:` 冲正，重分拣后按新指纹重新上报 |
| 回执对不上两版都留 | 本地版与回执版快照并列留底、挂起不覆盖、不重投 |
| 写入失败留住已确认的 | 已 confirmed 永不重发；失败项停留 pending，可整批或单份重投 |
| 可续作 | 状态 + 事件台账持久化到 localStorage，刷新后 hydrate，到期租约自动回收 |

页面提供「双师傅同交一位」一键演示，以及「注入网络故障」「下次回执对不上」两个开关。
